# 芦苇斑块跨图幅调查系统

湿地调查员核清跨图幅芦苇斑块的 Web 工具：按图幅行列上传/替换 16×16 的 0/1 掩膜 CSV，
自动跨片缝连通、编号、统计全图格数；调查员核实样方后按全图行列登记现场判定 0/1，
系统对照现行图幅列出一致/不符/缺测的格，并守护每次换片不把已和现场对上的格改错。
Flask + SQLite，Docker Compose 一键启动。

## 快速开始

```bash
docker compose up --build      # 打开 http://localhost:8080
```

本地开发（Python 3.11+）：

```bash
pip install -r requirements.txt -r requirements-dev.txt
python wsgi.py                 # http://localhost:8000
pytest tests/ -q               # 运行自测
```

## 规则约定

- 每片图幅 16×16，掩膜 CSV 为 16 行、每行 16 个 `0`/`1`（逗号分隔；兼容无逗号的 16 位串）。
- 全图坐标：图幅 `(sr, sc)` 的片内格 `(r, c)` → 全图 `(sr*16+r, sc*16+c)`，**行、列号均从 0 起计**。
- 值为 1 的格子共边（四邻）相连，片缝两侧同样相连。
- **斑块号** = 该斑块最北一行中最西一格的全图行列号，形如 `(8,10)`。
- 同位置重复上传即替换；其他图幅的片内连通关系不变，跨片拆并引起的编号与总格数随新版本一并更新。
- **样方 CSV**：每行 `全图行,全图列,值`（值只许 0/1；首行可为表头）。整表替换、独立编版
  （sv1、sv2…，与地图版 v1、v2… 各自编号）。同一格重复登记、坐标越界（0–15999）、
  值非法、空表均**整表拒收**；换表失败继续使用原表。

## 样方核查工作流

1. **登记**：调查员上传/替换样方 CSV，按全图行、列登记现场判定的 0/1。
2. **对照**：首页「样方对照」按现行图幅把样方格分为三类，并注明**地图版**与**样方表版**——
   - 一致：所在图幅已交付，图上值与现场判定相同；
   - 不符：所在图幅已交付，图上值与现场判定不同；
   - 缺测：所在图幅尚未交付，现行图幅无从核对。
3. **守护**：每次发布掩膜（含演示按钮）时，按**实际入库时生效的样方表**与**上一发布版**
   逐格判断——原本一致的格若在新版变为不符或缺测，列出这些格的坐标并**整片退回**（HTTP 409），
   原掩膜与斑块成果照常可查。逐格判定：修好一格不能抵消另一格的退步。
4. **分次修正**：原本不符或缺测的格不受守护约束，可以分多批改对/补交，每批只修一部分也会被接受。
5. **换代**：换样方表是调查员权限内的操作，新表生效后守护即按新表判断（旧表约束随之解除）。

## 网页功能

- **上传/替换图幅掩膜**：表单填图幅行列 + 选 CSV 文件（或直接粘贴文本）。校验失败返回 400，
  触发样方守护返回 409 并列出回归格坐标；两种失败都不改动已发布数据。
- **上传/替换样方表**：选 CSV 文件或粘贴文本，整表替换；重复坐标等非法输入整表拒收并沿用原表。
- **样方对照**：一致/不符/缺测三类清单（注明地图版与样方表版），每类最多列 200 格，
  完整清单见 `/api/comparison`。
- **在线试：样方核查与分次修正**（按钮 ④–⑨）——
  ④ 载入两片图幅 + 样方表（一致 3 · 不符 2 · 缺测 1）；
  ⑤⑥ 分两批把不符格 (4,4)、(4,5) 改对；⑦ 补交图幅 (1,0) 使缺测格 (20,3) 转一致；
  ⑧ 试投把已对齐格 (8,10) 改错的换片 → 被退回并列出坐标，版本与成果不变；
  ⑨ 演示重置（样方表换代后旧约束解除，可重新跑 ④→⑧）。
- **在线试：跨片合并/拆开**（按钮 ①–③）：原有演示保留；已上传样方表时同样受守护约束
  （例如清空会把一致格变成缺测而被退回）。
- **图幅列表 / 斑块汇总 / 全图预览**：颜色区分斑块，悬停看坐标与总格数。
- **选片查看**：`/sheet/<行>/<列>` 展示 16×16 网格与斑块号，并给出本片范围内的样方对照表。
- **JSON API**：`GET /api/state`（含 `sample_version` 与对照计数）、`GET /api/sheet/<行>/<列>`、
  `GET /api/samples`（生效样方表）、`GET /api/comparison`（三类完整清单，注明两版号）。

## 设计要点（对应需求）

- **掩膜与成果一并切换**：每次交片产生一个单调递增的版本，掩膜（`sheets`）、
  斑块成果（`patches`、`cell_patches`）在同一事务内写入并翻转 `meta.version`，
  查询永远只读某个完整版本，不会看到混搭。
- **样方表独立编版**：`samples` 按 `sample_version` 整体换版，单事务写入；
  校验（重复坐标/越界/非法值/空表）在写库前完成，失败不写库，原表继续生效。
- **按入库时生效的样方表守护**：交片先在事务外基于当前发布版重算，进入写事务
  （`BEGIN IMMEDIATE`）后才读生效样方表，与上一发布版逐格比对；因此重算斑块期间
  换表不被阻塞，而交片判断用的永远是提交那一刻的样方表。
- **逐格判定，不退让**：守护只看「原本一致 → 不符/缺测」的格集合，集合非空即整片退回；
  修好多少格都不能抵消任何一格的退步。原本不符/缺测的格可自由分次修正。
- **失败的交片/换表不改已发布数据**：校验在写库前完成，写库任何异常整体回滚。
- **并发按实际入库顺序生效**：交片走进程内写锁 + `BEGIN IMMEDIATE` 与版本号校验兜底，
  版本被抢先则基于最新成果重试；换表走独立锁与事务，与交片提交相撞时靠
  `busy_timeout` + 重试消化，互不长时间阻塞。
- **重算期间可查完整旧成果**：重算在事务外进行，算完才进写事务提交；
  重算进行中所有查询仍读到旧版本的完整成果。

## 实测结果（交付前自测）

- `pytest tests/ -q`：**32 passed**。在原有 17 项（编号规则、跨片拆并、失败隔离、并发、
  重算期间旧成果可读、演示接口、页面渲染）之上新增 15 项：
  样方解析规则（表头/重复坐标/非法值/越界/空表）、上传与对照（三类清单与两版号）、
  整表替换编版、重复坐标与非法 CSV 拒收且原表继续生效、一致格被改错/变缺测均 409 退回
  且成果不变、分次修正被接受、修好一格不抵消另一格退步、不符/缺测格不受守护、
  **重算进行中换表成功且交片按入库时生效的新表判断被退回**、演示 ④→⑨ 全流程、
  首页/片页对照渲染、`/api/state` 样方信息。
- gunicorn（1 worker × 8 线程，与容器内一致）实机冒烟：
  - 演示 ④→⑦：对照从 一致3/不符2/缺测1 逐步变为 一致6/不符0/缺测0（地图版 v1→v4，样方表版 sv1）；
  - ⑧ 退回换片：HTTP 409，报文列出 `(8,10)`，版本、掩膜、斑块成果不变；
  - 重复坐标样方表 → 400「换表被拒绝（沿用原表）：重复坐标 (8,10)」，sv 不变；
  - 网页表单手动换片破坏一致格 → 409 同样被退回；
  - 文件上传合法换表 → sv2 生效，对照全一致；
  - ⑨ 重置后重跑 ④ 成功；有守护时「清空全部图幅」被 409 退回（3 格将变缺测）；
  - 10 路并发 HTTP 交片 → 版本恰好 +10，数据一致。

## 待补事项

- 本环境无 Docker，`docker compose up` 未实际跑过；Dockerfile 与本地 gunicorn 冒烟
  使用同一启动命令（`gunicorn --workers 1 --threads 8 wsgi:app`），请在有 Docker 的
  机器上做一次 `docker compose up --build` 验证。
- 历史版本（掩膜、成果、样方表）永久保留，未做清理；数据量大时可加旧版本裁剪（保留最近 N 版）。
- 样方守护在每次交片时全量对照样方表，十万格级仍无压力；若样方规模极大可改为
  只对照本次变动图幅覆盖的格。
- 多副本水平扩展时写锁仅在单进程内有效（数据库侧版本校验仍保证正确性，但冲突重试会增多）；
  需要多副本时建议固定单写实例或引入队列。
- 行列号从 0 起计为本实现的明确约定；若业务习惯 1 起计，需统一调整展示层。
- 暂未提供“删除单片”接口（可用全 0 掩膜替换达到同样效果；受样方守护约束）。
- 样方表替换即换代，未做换表审批/留痕界面；如需审计谁在何时换了表，可加操作日志。
